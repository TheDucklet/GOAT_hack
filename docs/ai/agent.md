# Агент построения карточки

`backend/app/ai/agent/runner.py:run_agent(company_context, user_focus, event, tools, max_extra_searches=2)` строит карточку влияния события и выполняет повторный поиск, если проверка не подтвердила позицию банка. Backend вызывает его как `build_insight` через `app.ai.bridge`. Функция `insights/build.py:build_insight` из F-06 остаётся однопроходной версией для тестов и проверок.

## Состояние и шаги

Состояние запуска (`AgentRun`) хранит найденные фрагменты, выполненные запросы с результатами (`outcomes`), результаты проверок (`checks`), число итераций и дополнительных поисков, а контекст компании, факты события и признаки лежат в `Prepared`. Шаги записываются в трассу по мере выполнения.

1. **Подготовка.** Проверяется, что инструмент вернул ту же компанию, собираются факты события и признаки компании. Если проверенных фактов нет, агент останавливается с причиной `no_event_facts` без вызова модели и поиска.
2. **План.** Модель `qwen/qwen3.6-35b-a3b` получает заголовок и темы события, факты, признаки компании и совпадения, возвращает от трёх до пяти шагов анализа и один-два запроса к материалам банка. Если ответ невалиден, используются запасные запросы из заголовка и тем события.
3. **Поиск.** Для каждого запроса вызывается `tools.search_bank_analytics` на дату публикации события. В трассу пишутся запрос, найденные фрагменты, идентификаторы банковского evidence и признак исторических материалов.
4. **Карточка.** `compose_card` из F-06 строит `bank_view`, объяснения, риски, возможности и действия, проверяя утверждения кодом (основания, числа, дубли).
5. **Проверка.** Утверждения `bank_view` отдельным вызовом модели сверяются с процитированными фрагментами, заголовком и фактами события, вердикты `supported`, `insufficient` или `contradiction`. Утверждение, которое фрагмент подтверждает, но которое относится к другой теме (совпадают лишь отдельные слова), получает `insufficient` с причиной «не относится к событию». Не подтверждённые утверждения удаляются. Затем `check_card` определяет итог (`supported`, `insufficient`, `contradiction`) и причины:

   | Причина | Значение | Можно исправить поиском |
   | --- | --- | --- |
   | `no_bank_evidence` | материалы банка по запросам не найдены | да |
   | `only_historical` | найдены только материалы старше года | да |
   | `fragments_not_relevant` | фрагменты есть, но утверждений банка не получилось | да |
   | `bank_claims_rejected` | проверка отклонила утверждения банка и ни одного подтверждённого не осталось (или есть противоречие) | да |
   | `no_interpretation` | нет объяснения, подтверждённого признаками компании | нет |
   | `no_event_facts` | нет проверенных фактов события | нет |

6. **Повторный поиск.** Если итог не `supported` и причина исправима поиском, агент меняет запрос. Модель `google/gemma-4-26b-a4b-it` получает прежние запросы с числом найденных и пригодных фрагментов и описание проблемы и возвращает новый запрос с причиной. Запрос, по составу слов совпадающий с прежним, заменяется запасным (другие темы события, слова заголовка, вид деятельности компании). После поиска карточка строится заново, только если появились новые пригодные фрагменты.
7. **Предел.** Дополнительных поисков не больше двух (`MAX_EXTRA_SEARCHES`). После второго неудачного поиска агент останавливается с причиной `retry_limit_reached`, третий запрос не выполняется. `bank_view` остаётся `null`, а в `unknowns` записано, сколько уточняющих поисков выполнено, а использованные запросы и вердикты проверки остаются в трассе.

Утверждение банка остаётся в карточке только при явном вердикте `supported`. Отказ проверки (тайм-аут, неразбираемый ответ, пустые или неизвестные вердикты) даёт `unverified` и причину `bank_verification_failed`, которая повторным поиском не исправляется.

Причины остановки: `supported`, `retry_limit_reached`, `no_further_search_possible` (причина не исправима поиском) и `no_event_facts`.

## Трасса

Трасса в `envelope.trace` содержит версию агента, версию промпта, `plan`, `steps`, число итераций и дополнительных поисков, все запросы, результаты проверок (`checks`) и причину остановки. Шаги `steps` бывают следующих видов.

- `tool` – вызов `get_company_context`, `get_event`, `search_bank_analytics` с входом (запрос, дата), найденными фрагментами, идентификаторами evidence и признаком `purpose` (`initial` или `retry`).
- `llm` – вызов модели (`agent_plan`, `build_insight`, `agent_check`, `agent_query`) с `request_id`, токенами и стоимостью.
- `plan`, `check`, `retry`, `stop` – план и первые запросы, результат проверки с причинами и evidence, повторный поиск с предыдущими запросами, новым запросом и причиной, итоговая остановка.

Ключ и тексты запросов к модели в трассу не попадают, права проверяются инструментами backend.

## Три трассы

`docs/ai/agent-traces/` содержит три трассы, полученные командой `python -m app.ai.agent all` из каталога `backend` на выданном шлюзе. Банковский поиск идёт по локальному снимку `docs/ai/fixtures/bank-chunks.json` (195 фрагментов девяти документов, получен командой `python -m app.ai.rag export`), потому что интерпретатор со шлюзом не может подключиться к локальной базе.

| Файл | Сценарий | Результат |
| --- | --- | --- |
| `ordinary.json` | решение по ставке для строительной компании с кредитным продуктом (U_38174), материалы банка найдены первым поиском | `supported`, 1 итерация, 0 дополнительных поисков |
| `repeat-search.json` | то же событие для компании без кредитного продукта (U_9085), результаты двух первых запросов скрыты | проверка вернула `insufficient` (`no_bank_evidence`), агент составил новый запрос «денежно-кредитная политика влияние на девелопмент», нашёл фрагменты, `supported`, 2 итерации, 1 дополнительный поиск |
| `retry-limit.json` | пошлина на прокат для торговой компании (U_243), по теме нет материалов банка | найден один исторический материал, проверка вернула `insufficient` (`only_historical`), два новых запроса не дали пригодных фрагментов, `retry_limit_reached`, третьего поиска нет, `bank_view` равен `null` |

В трёх из четырёх запусков обычного сценария агент завершил работу за одну итерацию. В одном запуске проверка отклонила одно утверждение банка как недостаточно подтверждённое, и агент выполнил один дополнительный поиск и получил `supported`, в репозиторий записан одноитерационный запуск.

Стоимость одного прогона составляет от 0,18 до 0,27 руб. (три-пять вызовов модели).

## Ограничения

- Проверка утверждений банка опирается на модель и может ошибаться, подробная проверка выводов выполняется в F-09.
- Сценарий повторного поиска воспроизводится с помощью скрытия результатов первых запросов, так как в корпусе девяти документов тема ставки находится первым запросом.
- Лексический поиск не находит материалы без общих слов с запросом, поэтому новые запросы агента используют синонимы и более общие термины.
