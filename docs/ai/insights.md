# Карточка влияния события на компанию

Функция `backend/app/ai/insights/build.py:build_insight(company_context, user_focus, event, tools)` строит карточку по контракту `AIEnvelope` с `result=InsightResult` (`docs/contracts/ai.md`). Первая версия использует фиксированную последовательность шагов, агентный цикл повторного поиска добавляется в F-07 поверх тех же функций.

## Порядок шагов

1. **Проверка границы прав.** Инструмент `tools.get_company_context()` обязан вернуть ту же компанию, что и входной контекст, иначе функция завершается ошибкой `forbidden`. Идентификатор компании агент сам не меняет.
2. **Факты события.** Берутся проверенные факты `event.facts` из `summarize_event` вместе со ссылками на новостное evidence. Если фактов нет, а у публикаций есть evidence, используется цитата evidence. Если нет и этого, модель не вызывается, а в `unknowns` записано, что источников недостаточно.
3. **Признаки компании.** Из `CompanyContext.features` выбираются непустые значения 20 признаков (вид деятельности, регион, город, выручка, численность, возраст, стадия, внешняя торговля, форма собственности, тип клиента, семь банковских продуктов, группа). Каждый признак становится evidence с `kind=company` и локатором `features.<COLUMN>`. Выручка записывается точным числом и округлением (`3 609 087 410 руб. (около 3,6 млрд руб.)`), чтобы проверка чисел принимала обе формы. Код отдельно считает совпадения события и компании (отрасль, регион, страна, продукт) и передаёт их модели.
4. **Банковские фрагменты.** Дважды вызывается `tools.search_bank_analytics` (заголовок события и его темы) на дату публикации события. Исторические материалы (старше года) в вывод не попадают, фрагменты с известной датой идут раньше фрагментов без даты, берутся не больше четырёх. Каждый фрагмент становится evidence с `kind=bank`, документом, версией и страницей.
5. **Генерация.** Модель `qwen/qwen3.6-35b-a3b` получает в JSON новости, признаки компании, фокус пользователя, совпадения и фрагменты банка и возвращает `bank_view`, `ai_interpretation`, `risks`, `opportunities`, `actions` и `unknowns`. Идентификаторы источников подаются короткими метками `N1`, `C3`, `B2`, потому что длинные UUID модель искажает при копировании.
6. **Проверка утверждений кодом.** Метка заменяется настоящим идентификатором, неизвестные метки отбрасываются, метки удаляются из текста. Утверждение отбрасывается, если оно без оснований, длиннее 600 символов, дублирует другое или содержит число, которого нет во входных данных (поэтому рублёвый эффект без суммы не появляется). `bank_view` оставляет только банковские основания. Объяснение в `ai_interpretation` должно ссылаться минимум на один признак компании и минимум на одно исходное основание (факт события или фрагмент банка). Риски, возможности и действия без собственных меток наследуют основания объяснения. Если объяснений не осталось, запрос повторяется один раз с температурой 0,3.
7. **Неизвестное.** К перечню модели код добавляет причины, которые знает точно: нет банковских материалов или есть только исторические (`bank_view=null` и пояснение), дата банковского материала неизвестна, при событии про ставку и кредиты не известны сумма долга и тип ставки (для компании с кредитным продуктом в данных есть только наличие продукта, для компании без него неизвестен долг в других банках).

## Результат и трасса

Возвращаются `facts` (из события), `bank_view` (список или `null`), `ai_interpretation`, `risks`, `opportunities`, `actions`, `unknowns`, `evidence_refs` (объединение ссылок) и `trace_id`. Список `evidence` содержит только новые источники (банковские и клиентские), новостные evidence уже есть в БД. Идентификаторы нового evidence детерминированы (UUID5 от компании, версии профиля и признака либо от документа, версии, страницы и цитаты), поэтому повторная публикация одной карточки не конфликтует с ранее сохранённым evidence.

Трасса `trace` хранит версию промпта, план, вызовы инструментов с запросами и найденными фрагментами, вызов модели с `request_id`, токенами и стоимостью, предложенные признаки, совпадения, отброшенные утверждения с причинами и причину завершения.

## Примеры

`docs/ai/insight-examples.json` содержит четыре карточки на реальных профилях из `df_Uid_data_hack.csv` (профили в `docs/ai/fixtures/companies.json`) и двух событиях из `docs/ai/fixtures/events.json`:

| Событие | Компания | Различие в карточке |
| --- | --- | --- |
| решение по ключевой ставке | строительная компания с кредитным продуктом (U_38174) | нагрузка по существующим кредитам, неизвестны сумма долга и тип ставки |
| решение по ключевой ставке | строительная компания той же отрасли и региона без кредитного продукта (U_9085) | влияние через лизинг и депозиты, неизвестен долг в других банках |
| пошлина на прокат | оптовая торговля металлами с внешней торговлей с Китаем (U_243) | совпадают отрасль и страна, риск роста закупочных цен |
| пошлина на прокат | оптовая торговля металлами без внешней торговли (U_2883) | совпадает только отрасль, влияние косвенное |

Ни в одной карточке нет утверждений без оснований, отброшенных утверждений нет, банковская позиция по ставке подтверждена страницей PDF, для новости о пошлине банковских материалов нет и это записано в `unknowns`. Каждая карточка стоит около 0,11-0,13 руб.

Поиск по базе документов и вызов модели нельзя выполнить одним процессом на машине, где интерпретатор Python с шлюзом работает через туннель, поэтому результаты поиска записываются в снимок `docs/ai/fixtures/bank-search-snapshot.json`. Команды из каталога `backend`:

```bash
python -m app.ai.insights snapshot
python -m app.ai.insights generate
```

Первая команда читает PostgreSQL (`DATABASE_URL`, индекс из `python -m app.ai.rag reindex`) и обновляет снимок, вторая использует снимок и выданный шлюз (`AI_LLM_API_KEY`) и записывает карточки.

## Ограничения

- Последовательность шагов фиксирована, при пустом поиске запрос не уточняется (F-07).
- Проверка подтверждает наличие оснований и чисел, но не логику вывода, смысл утверждений оценивает проверка в F-09.
- Совпадения компании и события вычисляются только по отрасли, региону, стране и продуктам, связи с контрагентами в карточке не используются.
