# Распознавание банковских PDF

Девять PDF аналитического центра Альфа-Банка (64 страницы) не содержат текстового слоя, поэтому `pypdf` возвращает пустой текст. Распознавание выполняет разрешённая кейсом модель `qwen/qwen3-vl-30b-a3b-instruct` через общий шлюз `call_llm` (см. `docs/ai/providers.md`). Локальный OCR не используется, так как страницы содержат таблицы, графики и подписи значений, которые классические движки с русским словарём теряют или искажают.

## Порядок обработки

Функция `ingest_bank_document(document, path)` в `backend/app/ai/ocr/ingest.py` вызывается worker-процессом после загрузки PDF.

1. Проверяются существование файла и совпадение числа страниц с `document.page_count`, иначе поднимается `AIError` с кодом `not_found` или `invalid_ocr`.
2. Каждая страница отрисовывается библиотекой `pypdfium2` в PNG (300 dpi, длинная сторона не больше 3600 пикселей) и целиком отправляется модели с запросом вернуть JSON `{text, title, date_text}` при температуре 0. Промпт лежит в `backend/app/ai/ocr/engine.py:SYSTEM_PROMPT`, его версия `OCR_PROMPT_VERSION` входит в ключ кеша.
3. Если ответ невалиден (например, модель зациклилась на подписях графика и упёрлась в лимит токенов) или пуст, страница режется на фрагменты высотой до 1800 пикселей по самой «тихой» строке между блоками (по числу резких перепадов яркости, поэтому разрез не проходит через текст на тёмном фоне). Каждый фрагмент распознаётся отдельно, при неудаче повторяется со сменой температуры и штрафом за повторы. Фрагмент без текста (фотография) допустим.
4. Если страница не дала текста длиной хотя бы 3 символа, она получает статус `failed` и причину (`empty_text`, `invalid_json`, `timeout` и другие коды `call_llm`). Если хотя бы одна страница `failed`, документ целиком отклоняется ошибкой `invalid_ocr` с перечнем номеров страниц. Неудачный результат не индексируется и в кеш не попадает.
5. Текст каждой страницы режется на фрагменты по 1200 символов с перекрытием 200 (`backend/app/ai/rag/chunking.py`). Граница фрагмента смещается к ближайшему переводу строки, концу предложения или пробелу. Поле `page` фрагмента равно номеру страницы PDF с единицы, а не порядку фрагмента.

Опыт отладки лёг в основу выбора параметров. Разрешение 150 dpi на страницах формата A3 давало потерю около половины контрольных фраз (6 из 12), 250 dpi – одной из 12, 300 dpi – ни одной. Разрезание страницы на части ухудшало точность текстовых страниц, так как разрез попадал внутрь абзаца, поэтому фрагменты используются только как запасной путь. Запрет описывать картинки в промпте нужен потому, что на обложке без текста модель выдумывала абзац о добыче золота.

## Название и дата

Название берётся из поля `title` первой страницы, при его отсутствии – из первой непустой строки. Строки вида «Центр макроэкономического анализа», рубрика «Рынок облигаций» и дата не считаются названием.

Дата документа определяется по первой странице в таком порядке.

1. Дата из `date_text`, если та же дата встречается в распознанном тексте.
2. Первая полная дата в первых 900 символах страницы.
3. День и месяц без года, год берётся как самый частый из годов на странице, не позднее текущего.
4. Строка «Месяц ГГГГ» на титульной странице, дата принимается равной последнему дню месяца.

Даты позже текущего дня отбрасываются, чтобы срок погашения облигации не стал датой публикации. Распознаются форматы «11 сентября 2026», «14.09.2026», «15 Apr 2021» и «Sep 11, 2026». Если дата не найдена, `document_date` равен `null`, а признак `date_unknown` истинен. Дата из имени файла не используется.

Название и SHA-256 хеш файла записываются в `docs/ai/ocr-report.json`, потому что модель `IngestResult` в backend содержит только дату и фрагменты.

## Кеш и стоимость

Результаты страниц кешируются на диске в `AI_OCR_CACHE_DIR` (по умолчанию `storage/ai-cache/ocr/<sha256>/<версия промпта>-pNNN.json`) вместе с числом токенов и стоимостью. Повторная загрузка того же файла не обращается к модели. Обработка всех 64 страниц стоит 13,9 руб. (581 тыс. входных и 70 тыс. выходных токенов), страница занимает от 30 до 130 секунд, поэтому таймаут OCR-запроса увеличен до 240 секунд (`AI_OCR_REQUEST_TIMEOUT_SECONDS`), а страницы обрабатываются тремя потоками.

## Ограничения распознавания

- Модель изредка пропускает строки плотного двухколоночного текста (в ручной проверке на пяти страницах потеряно от одной до полутора строк на странице), поэтому полнота ниже 100%.
- Значения на подписях графиков не переносятся, сохраняются заголовки, легенда и оси.
- Результаты ручной проверки чисел и дат лежат в разделе `manual_checks` файла `docs/ai/ocr-report.json`.

## Настройка

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `AI_OCR_DPI` | 300 | разрешение отрисовки страницы |
| `AI_OCR_MAX_SIDE_PIXELS` | 3600 | предел длинной стороны изображения |
| `AI_OCR_PAGE_MAX_TOKENS` | 4500 | предел выходных токенов при распознавании страницы целиком |
| `AI_OCR_MAX_TOKENS` | 3500 | предел выходных токенов на фрагмент |
| `AI_OCR_TILE_HEIGHT_PIXELS` | 1800 | высота фрагмента при запасном разрезании |
| `AI_OCR_REQUEST_TIMEOUT_SECONDS` | 240 | таймаут одного запроса |
| `AI_OCR_MIN_PAGE_CHARS` | 3 | минимальная длина текста страницы |
| `AI_OCR_WORKERS` | 3 | число параллельных страниц |
| `AI_OCR_PAGE_ATTEMPTS` | 2 | число попыток на фрагмент |
| `AI_OCR_CACHE_DIR` | `storage/ai-cache/ocr` | каталог кеша |
| `AI_RAG_CHUNK_CHARS` | 1200 | размер фрагмента текста |
| `AI_RAG_OVERLAP_CHARS` | 200 | перекрытие фрагментов текста |

## Команды

Из каталога `backend` при заданном `AI_LLM_API_KEY`:

```bash
python -m app.ai.ocr count --dir ../data2
python -m app.ai.ocr probe --pdf ../data2/Gold_digest_August26.pdf --pages 2
python -m app.ai.ocr report --dir ../data2 --output ../docs/ai/ocr-report.json
```

Команда `probe` печатает распознанный текст выбранных страниц, `report` обрабатывает все PDF каталога и записывает отчёт. Ручные проверки (`manual_checks`) при повторной записи отчёта сохраняются.
