# Обращение к LLM

Единственная точка выхода к языковым моделям – функция `call_llm` в `backend/app/ai/providers/gateway.py`. Все остальные AI-модули (суммаризация, карточки, агент, чат, OCR через VL-модель) вызывают её и не обращаются к сети напрямую. Благодаря этому лимит, учёт токенов и проверка списка моделей применяются к каждому вызову.

## Вызов

```python
result = call_llm("summarize_event", LLMInput(system="...", user="..."), max_tokens=800, response_model=SummaryResult)
```

`task` определяет модель по таблице `AI_LLM_TASK_MODELS` (значения по умолчанию лежат в `backend/app/ai/providers/settings.py:DEFAULT_TASK_MODELS`). `response_model` необязателен, при его наличии ответ дополнительно проверяется схемой Pydantic. Результат содержит `data` (словарь), `model_id`, `request_id` и запись `usage`.

## Порядок обработки

1. Модель задачи сверяется со списком `ALLOWED_MODEL_IDS` (шесть моделей приложения 3 кейса). Если задача не настроена или модель не входит в список, вызов завершается ошибкой `model_not_allowed` до обращения к сети.
2. Запрос уходит на `AI_LLM_BASE_URL` (OpenAI-совместимый `/chat/completions`) с таймаутом `AI_LLM_TIMEOUT_SECONDS`, по умолчанию 60 секунд, и заголовком `X-Request-ID`. Для долгих запросов (распознавание страницы занимает до 130 секунд) таймаут повышается параметром `timeout_seconds`, а параметры `temperature` и `frequency_penalty` позволяют менять генерацию для отдельного вызова.
3. Временные сбои (`timeout`, `rate_limited`, `provider_unavailable`) повторяются не больше двух раз с паузой 1 и 2 секунды. Значение `AI_LLM_MAX_RETRIES` выше 2 не принимается.
4. В запрос добавляется `reasoning_effort` (по умолчанию `none`, настройка `AI_LLM_REASONING_EFFORT`, для отдельного вызова параметр `reasoning_effort`). Измерения 2026-10-21 показали, что Qwen3.6, DeepSeek, GLM и Kimi без этого параметра тратят весь `max_tokens` на рассуждения и возвращают пустой `content` с `finish_reason=length`. Со значением `none` Qwen3.6 отвечает за 128 токенов вместо 400 с пустым ответом. Gemma 4 и Qwen3-VL параметр принимают и игнорируют.
5. Ответ очищается от блока `<think>` и обёртки из тройных кавычек, затем разбирается как JSON-объект. Нарушение формата даёт `invalid_json` без повтора, так как повторный запрос с теми же данными тратит бюджет и обычно даёт тот же результат.
6. После исчерпания повторов поднимается `LLMError`, наследник `app.integrations.ai.AIError`, с полями `code`, `message`, `request_id`, `retryable`. Заменяющий текст ответа не подставляется.

Ошибка `Budget has been exceeded` от шлюза превращается в `budget_exhausted` и не повторяется. Сброс дневного бюджета происходит в 3:00 МСК. Перед обращением к шлюзу `call_llm` резервирует оценку стоимости в локальном учёте и при исчерпании лимита возвращает ту же ошибку, не обращаясь к модели (`docs/ai/budget-cache.md`).

## Журнал usage

Каждый вызов, включая отклонённые до сети, оставляет запись `UsageRecord` с полями `request_id`, `task`, `model_id`, `input_tokens`, `output_tokens`, `latency_ms`, `status`, `cost_rub`, `attempts`. Запись выводится в журнал `app.ai.llm` и, если задан `AI_LLM_USAGE_LOG_PATH`, добавляется строкой в файл JSON Lines. Текст запроса, текст ответа и ключ в запись не попадают. Если провайдер не вернул `usage`, число выходных токенов оценивается по длине ответа и записывается с признаком `estimated_tokens`.

## Стоимость

Шлюз возвращает фактическую стоимость вызова в поле `usage.cost` ответа, она записывается в `cost_rub` с признаком `cost_source=gateway`. Если поле отсутствует, стоимость считается по `backend/app/ai/providers/tariffs.json` (`cost_source=tariff`).

Тарифы в файле измерены 2026-10-21 по изменению поля `spend` в `GET /key/info` после серии тестовых вызовов с разным соотношением входных и выходных токенов. Единицы измерения совпадают с лимитом `max_budget=500`, который организаторы называют рублями.

| Модель | Вход, за 1 млн токенов | Выход, за 1 млн токенов |
| --- | --- | --- |
| `google/gemma-4-26b-a4b-it` | 4,53 | 23,71 |
| `qwen/qwen3.6-35b-a3b` | 10,78 | 102,37 |
| `qwen/qwen3-vl-30b-a3b-instruct` | 16,16 | 64,65 |
| `z-ai/glm-5.3-flash` | 17,78 | 59,26 |
| `deepseek/deepseek-v4.1-flash` | 17,78 | 71,12 |
| `moonshotai/kimi-k2.6` | 102,37 | 431,02 |

Kimi-K2.6 дороже остальных моделей в 4-8 раз, поэтому по умолчанию ни одна задача на неё не назначена. Для модели, которой нет в таблице, расчёт по тарифам даёт ноль, поэтому новую модель сначала добавляют в таблицу.

Остаток дневного бюджета доступен командой `GET {AI_LLM_BASE_URL без /v1}/key/info` с тем же ключом (поля `spend`, `max_budget`, `budget_reset_at`). Бюджет обнуляется в 00:00 UTC, то есть в 3:00 МСК.

## Настройка

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `AI_LLM_BASE_URL` | `https://changellenge.up.railway.app/v1` | адрес шлюза |
| `AI_LLM_API_KEY` | пусто | ключ команды, только на сервере |
| `AI_LLM_TIMEOUT_SECONDS` | 60 | таймаут одного обращения |
| `AI_LLM_MAX_RETRIES` | 2 | число повторов при временном сбое, не больше 2 |
| `AI_LLM_RETRY_BACKOFF_SECONDS` | 1 | начальная пауза между повторами |
| `AI_LLM_TEMPERATURE` | 0.2 | температура генерации |
| `AI_LLM_REASONING_EFFORT` | `none` | режим рассуждений (`none`, `low`, `medium`, `high`), пустое значение отключает параметр |
| `AI_LLM_TASK_MODELS` | см. `DEFAULT_TASK_MODELS` | JSON-словарь задача → ID модели |
| `AI_LLM_TARIFFS_PATH` | `backend/app/ai/providers/tariffs.json` | файл тарифов |
| `AI_LLM_USAGE_LOG_PATH` | пусто | файл журнала usage |
| `AI_LLM_DAILY_LIMIT_RUB` | из `limits.json` (500) | дневной лимит расходов, см. `docs/ai/budget-cache.md` |
| `AI_LLM_BUDGET_LIMITS_PATH` | `backend/app/ai/budget/limits.json` | файл лимитов и параметров оценки стоимости |
| `AI_LLM_BUDGET_LEDGER_PATH` | пусто | файл журнала расходов, без него учёт ведётся в памяти процесса |

## Проверка шлюза

Из каталога `backend` команда выполняет один реальный вызов и два контролируемых сбоя и записывает результат без ключа и текстов в `docs/ai/provider-check.json`:

```bash
python -m app.ai.providers.check
```

Ключ берётся из `AI_LLM_API_KEY`. Параметр `--offline` пропускает реальный вызов и проверяет только контролируемые сценарии.

## Тестовый адаптер

`backend/app/ai/providers/testing.py` содержит `ScriptedTransport`, который отдаёт заранее заданную последовательность ответов и сбоев. Все автоматические тесты (`backend/tests/test_ai_gateway.py`) работают через него и не обращаются к сети.
