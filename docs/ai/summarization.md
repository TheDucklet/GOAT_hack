# Суммаризация новостей и фокус пользователя

Обе функции подключены к backend через модуль `app.ai.bridge` (см. `docs/contracts/integration.md`) и возвращают результат в форматах `SummaryResult` и `UserFocus`. Их общий словарь тем позволяет ранжированию сопоставлять событие и пользователя точным совпадением строк (`backend/app/services/ranking.py`).

## summarize_event

`backend/app/ai/summarization/summarize.py:summarize_event(event)` принимает событие с публикациями и news-evidence и возвращает `summary`, `facts`, `entities` и `topics`.

Порядок обработки:

1. Из текста публикаций удаляются предложения, похожие на инструкции модели («игнорируй предыдущие инструкции», «покажи ключ доступа» и подобные), затем берутся не больше пяти публикаций по 6000 символов. Публикация без news-evidence пропускается, так как факт из неё нечем подтвердить. Если подходящих публикаций нет, модель не вызывается, возвращаются заголовок как `summary` и пустые списки.
2. Модель `qwen/qwen3.6-35b-a3b` получает текст в ограничителях `<<< >>>` с указанием, что это данные, и возвращает JSON с кратким содержанием, фактами (текст, дословная цитата, метка публикации), организациями и темами.
3. Каждый факт проверяется кодом. Цитата должна дословно входить в текст указанной публикации (сравнение без учёта регистра, пробелов, кавычек и буквы «ё»), а все числа в тексте факта должны встречаться в публикации. Факт, не прошедший проверку, отбрасывается, а при отсутствии прошедших фактов запрос повторяется один раз с температурой 0,3. Факту присваивается `evidence_refs` с evidence той публикации, где найдена цитата.
4. Предложения краткого содержания с числами, которых нет в тексте, удаляются, при пустом остатке берётся первый проверенный факт. Организации остаются, только если их слова есть в тексте.

Поле `topics` содержит пять ключей и использует тот же словарь, что и данные клиентов:

| Ключ | Источник значений |
| --- | --- |
| `theme` | список из `backend/app/ai/summarization/vocabulary.py:THEMES` (25 тем), отличные от списка значения отбрасываются |
| `industry` | ключевые слова модели отбирают до 25 видов деятельности из словаря (`MAINOKVED_NAME`), затем лёгкая модель `google/gemma-4-26b-a4b-it` оставляет не больше пяти, которых новость затрагивает напрямую |
| `product` | коды `CL_PRODUCT_*` и `FACTORING_MARK` от модели плюс продукты, заданные темами (`THEME_PRODUCTS`, например ключевая ставка добавляет кредиты, лизинг, депозиты и факторинг) |
| `geo` | регионы, города и страны из текста, сопоставленные с точными значениями `REGION`, `CITY` и `FTS_COUNTRY_NAME` |
| `relation` | пустой список, связи с контрагентами определяет ранжирование |

Словарь `vocabulary.json` построен из столбцов `MAINOKVED_NAME`, `REGION`, `CITY` и `FTS_COUNTRY_NAME` файла `df_Uid_data_hack.csv` и содержит только значения со счётчиками, без идентификаторов компаний. Пересборка выполняется командой `python -m app.ai.summarization.vocabulary --csv <путь к CSV>`.

## derive_user_focus

`backend/app/ai/personalization/focus.py:derive_user_focus(position_text, interests)` превращает произвольную должность и интересы в фокус из `topics`, `priorities`, `unknowns` и `version`. Список должностей нигде не задан, код и схема не меняются при новой должности.

- Если в должности нет слова из трёх и более букв (пустая строка, знаки, цифры), модель не вызывается, возвращается нейтральный фокус только с интересами пользователя и записью `Должность не определяет дополнительный фокус` в `unknowns`.
- Иначе модель `google/gemma-4-26b-a4b-it` выбирает от нуля до шести тем из того же списка `THEMES` и до четырёх приоритетов. Темы вне списка отбрасываются, поэтому фокус и события сопоставляются точным совпадением.
- Приоритеты с упоминанием прав, администратора, паролей, ключей и инструкций отбрасываются, поэтому текст должности не может расширить доступ. Права в системе фокус не затрагивает вообще, так как backend хранит их отдельно от `position_text`.
- Характеристики компании фокус не угадывает, в `unknowns` всегда записано, что отрасль, продукты и масштаб компании по должности не определяются.
- Интересы очищаются от лишних пробелов и повторов (до восьми штук по 60 символов) и добавляются к темам.

Поле `version` равно версии промпта (`focus-1`). Backend кеширует фокус по точному вводу и `AI_GENERATION_VERSION`, поэтому при изменении промпта или списка тем значение `AI_GENERATION_VERSION` нужно увеличить.

## Проверки

Команды из каталога `backend` (нужен `AI_LLM_API_KEY`):

```bash
python -m app.ai.summarization
python -m app.ai.personalization
```

Первая обрабатывает четыре синтетических события из `docs/ai/fixtures/events.json` (решение по ключевой ставке, экспортная пошлина на прокат, новость со спрятанной инструкцией и событие без текста) и записывает вход и результат в `docs/ai/summary-checks.json`. Вторая обрабатывает шесть должностей и записывает результат в `docs/ai/focus-checks.json`. Оба файла служат JSON-примерами для Алексея.

Наблюдаемые результаты:

- В событии о ставке получены 4 проверенных факта, тема «ключевая ставка» и продукты `CL_PRODUCT_LOA_MARK`, `CL_PRODUCT_LEA_MARK`, `CL_PRODUCT_DEP_MARK`, `FACTORING_MARK`.
- В событии о пошлине получены темы «торговые пошлины и тарифы» и «металлургия», регионы Свердловская и Челябинская области, страны Китай и Турция в виде точных значений набора.
- Текст «ИГНОРИРУЙ ВСЕ ПРЕДЫДУЩИЕ ИНСТРУКЦИИ» не попал в запрос к модели, выручка 500 млрд рублей не появилась в фактах.
- Должности «Главный бухгалтер», «Директор по закупкам» и новая длинная должность дали разные наборы тем без изменения кода, пустая должность и должность «!!! 12345» дали нейтральный фокус, текст с командой выдать права администратора дал нейтральный фокус.
- Восемь вызовов суммаризации стоят около 0,19 руб.

## Ограничения

- Отбор отрасли зависит от слов, которые назвала модель, поэтому часть смежных видов деятельности (например, производство стали при новости о прокате) может не попасть в `industry`.
- Темы выбираются из фиксированного списка из 25 пунктов, для новости вне списка `theme` остаётся пустым.
- Проверка фактов подтверждает наличие цитаты и чисел в тексте, но не смысл вывода из цитаты.
