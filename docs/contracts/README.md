# HTTP-контракт A-01

Источник истины — `backend/app/contracts.py` и `backend/app/schemas.py`.
`openapi.json` генерируется командой `python -m app.cli export-openapi` из backend/.
Примеры в `examples.json` проверяются тестами на соответствие этим же схемам.

Каждая операция имеет входы, успешный статус/результат и `x-access`:

- `rule` — правило авторизации для будущей реализации;
- `csrf_required` — обязательность X-CSRF-Token после входа для изменяющих операций.

`x-implementation-status=contract-only` означает, что функция ещё не реализована;
реальный вызов возвращает 501 с ErrorOut. Публичная регистрация принимает только
email/password; user/admin — системная роль, а position_text — произвольная строка
в членстве компании. Должность не даёт административных разрешений.

После входа предполагается HttpOnly cookie `goat_session`; GET `/me` возвращает
csrf_token. Права проверяются сервером в реализации соответствующих задач.

Job: `{id,status,result,error}`, status — queued/running/done/failed.
ErrorOut: `{code,message,request_id,field_errors}`.
POST Insight: 200 с InsightOut либо 202 с JobOut. Получение сохранённой карточки:
GET `/insights/{insight_id}`. После ответа job чата клиент перечитывает историю.
Порядок сообщений задаётся sequence. PDF-страницы в evidence нумеруются от 1.

Схема БД дополнительно включает источники публикаций, аудит и таблицы клиентских
связей для следующих задач. В ветке есть только их структура, без импорта или обработки.
AI-поля описывают формат обмена и подлежат согласованию с Фёдором в F-01;
примеры не являются результатами работы модели.
