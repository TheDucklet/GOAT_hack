# Контракт API

Компания теперь выдаётся как CompanyContext v2: [семантика данных](../data/data-semantics.md),
`company-context-v2.schema.json` и общие `company-context-v2-examples.json`.
Tagless CompanyContext v1 сохранён для совместимости входов AI и старых fixtures.

Контракт бизнес-влияния v2, правила совместимости v1, владельцы полей и общие
fixtures опубликованы в [insight-v2.md](insight-v2.md). Рабочий генератор поддерживает v2;
v2-схемы используются pipeline F-14/A-15 и UI R-05/R-13; чтение v1 сохранено для прежних результатов.

Snapshot v2 в R-13 возвращает механизм, обоснование влияния, горизонт, сроки актуальности и неизвестные из сохранённого Insight одним ответом feed. Поля необязательны для совместимости; для неподготовленных/устаревших элементов персональные поля пусты. OpenAPI, TypeScript и feed JSON Schema/fixtures генерируются из backend-схем; `scripts/export_feed_contracts.py --check` проверяет актуальность fixtures. Деталь открывается по тому же insight_id, дополнительные запросы за каждым preview не нужны.

Схемы определены в backend/app/schemas.py. Описание операций и правил доступа находится в backend/app/contracts.py. В накопленной реализации этой ветки все объявленные операции подключены к обработчикам и отмечены в OpenAPI значением implemented. В начальной ветке контракта они были отмечены значением contract-only и возвращали 501. Это состояние относится к ранней задаче.

Из каталога backend OpenAPI обновляется следующей командой.

```powershell
..\.venv\Scripts\python.exe -m app.cli export-openapi
```

Примеры examples.json синтетические и проверяются по тем же схемам. Результат Job содержит id, status, result и error. Ошибка содержит code, message, request_id и field_errors. Правила авторизации и необходимость защитного заголовка заданы в x-access.

После входа браузер передаёт HttpOnly cookie. GET /me возвращает csrf_token. Для изменяющих запросов требуется X-CSRF-Token. Должность хранится произвольной строкой в членстве компании. Системная роль назначается независимо от должности.

Создание карточки возвращает готовую карточку с кодом 200 или задание с кодом 202. После завершения задания читается сохранённая карточка. После завершения ответа чата перечитывается история. Сообщения упорядочены по sequence. Нумерация страниц PDF начинается с единицы.

Подробные правила обмена с frontend и AI находятся в integration.md. Настоящие AI модули и общая сборка ещё требуют совместной приёмки.
