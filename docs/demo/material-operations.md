# Обновление банковского корпуса и новостей · R-08

Оператор входит готовой учётной записью admin; подготовка аккаунтов описана в [R-07](access-management.md). Используйте HTTP-режим и работающие API/worker/PostgreSQL. Системная роль проверяется сервером, должность на неё не влияет.

## Банковский PDF

1. Откройте «Администрирование» → «PDF» (`/admin/documents`). Выберите исходный PDF не более 50 МиБ и нажмите «Загрузить и проиндексировать». Выбор файла сам по себе ничего не отправляет. Сервер проверяет содержимое, шифрование и число страниц, а не доверяет расширению/MIME.
2. После ответа 202 начинается фоновое OCR/index. Интерфейс показывает принятый job и опрашивает его каждые 2 с. Если ожидание превысило 120 с, «Повторить» читает то же задание; новый OCR автоматически не создаётся. Уход со страницы отменяет ожидание клиента, но сервер продолжает уже принятую обработку.
3. После done список обновляется: filename, дата документа или «Неизвестна», число страниц, status/error. Дата не берётся из времени загрузки. «Основание загруженного PDF» открывает сохранённый распознанный фрагмент первой страницы и защищённый оригинал PDF на `#page=1`. То же основание доступно в завершённом задании после reload.
4. Повторная загрузка тех же байтов возвращает прежний документ по SHA-256. Если он уже готов, новый job не создаётся. Если обработка failed, используйте «Повторить индексацию» у документа или соответствующий failed в «Заданиях». Для готового документа доступно явное «Перестроить индекс».
5. После обновления корпуса прежние аналитические карточки могут стать stale по существующей политике версий; их обновление выполняется отдельно, а не при каждом открытии PDF.

Для сканов OCR требует серверного AI-ключа и разрешённого модельного шлюза. Настройте игнорируемый `.env.ai` по `.env.ai.example`; пример не содержит ключ. Ни ключ, ни PDF не передаются во frontend build. OCR распознаёт страницы с номерами, сервер проверяет полноту и сохраняет chunks/index_version. Неполный или ошибочный OCR не становится готовым документом. После успешной индексации evidence создаётся через общий валидатор и содержит настоящий фрагмент, страницу, дату и версию. Изменённый индекс создаёт отдельное immutable evidence.

## Новости

В `/admin/news` отображаются source/URL, дата публикации или «Неизвестна», глобальная visible и processing_status. Ссылки допускают только HTTP(S) без credentials; HTML и тексты модели не исполняются.

«Скрыть для всех» требует подтверждения и исключает событие из общей выдачи. «Вернуть всем» возвращает глобальную видимость. Это операторское изменение для всех пользователей; персональное «Скрыть инсайт» относится к R-09. Решение не применяется оптимистически: строка меняется только после подтверждённого ответа сервера.

«Собрать новости» ставит существующий collect_news; «Повторить обработку» использует существующий summarize для выбранного события. Повтор queued/running возвращает тот же активный job. После failed новый запуск возможен только явно. Общая worker-политика ограниченно повторяет временные ошибки внутри того же задания; это не новая отправка из UI.

## Задания и ошибки

`/admin/jobs` показывает ID, тип операции, ID материала для PDF/новостей, состояние, время получения, число попыток и ошибку. Полный payload, текст чата и клиентский профиль в административные метаданные не добавляются. «Проверить задание» выполняет только GET. Для failed PDF/summarize/collect доступны соответствующие существующие POST; остальные типы повторяются на своих экранах.

Сетевой таймаут не доказывает, что сервер не принял изменение. Если job известен, продолжайте его чтение. Если ответ POST потерян, сначала перечитайте список; повтор upload дедуплицируется байтами, повтор активного reindex/retry/collect — общим ключом очереди. Кнопки не создают двойную отправку; в PostgreSQL столкновение параллельных постановок возвращает один активный job. Ошибка не подменяется успешным ответом, автоматического перехода на mock нет.

401 возвращает ко входу, 403 очищает показанные записи. Во время запроса меняющие кнопки отключены. «Обновить список» начинает чтение с первой страницы; «Загрузить ещё» продолжает по 50 записей.

Расширенный OCR-dashboard, массовые операции и коннектор закрытого Alfa Research остаются P2. UI не изображает доступ к закрытому источнику.

## Воспроизведение приёмки

Требуются Docker Compose с `!override`, Playwright 1.58.0/Edge, предоставленный `../data2/Inflation_tracker_02.pdf` и явно разрешённое использование настроенного OCR-шлюза. Сценарий отправляет изображения трёх страниц внешней модели; сначала согласуйте это для своего окружения. Ключ находится только в игнорируемом `.env.ai`. Тестовый лимит — 5 ₽ на изолированное хранилище бюджета.

```powershell
$env:IMAGE_TAG='r08-check'
docker compose -p goat-r08-check -f compose.yaml -f frontend/tests/compose.r08.yaml up --build -d --wait
python frontend/tests/material_smoke.py --channel msedge --project goat-r08-check --output artifacts/r08-browser
docker compose -p goat-r08-check -f compose.yaml -f frontend/tests/compose.r08.yaml stop
Remove-Item Env:IMAGE_TAG
```

Используются localhost:8089, отдельные тома и только пустая БД `goat_r08`. Скрипт отказывается менять существующие аккаунты/корпус. Для повторного полного прогона возьмите новое имя `goat-r08-*`; прежние тома сохраняются. Фикстуры создают только синтетические аккаунты, новость для видимости и намеренно отсутствующий файл для отказа. Распознаваемый PDF настоящий; HTTP/worker/OCR/evidence не подменяются.

В сценарии collection и news retry проверяются до queued с остановленным тестовым worker: отдельные внешние новостные/LLM-вызовы этим тестом не выполняются. Worker остаётся остановленным после проверки; запуск всего проекта без остановки/проверки очереди начнёт выполнять эти принятые задания. [Результаты и границы R-08](../qa/r-08.md).
