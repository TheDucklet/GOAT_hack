# Демонстрация и испытания перед сдачей · R-12

Начните с [README](../../README.md): clone, env, четыре healthy-контейнера, `seed-showcase`, банковский корпус и `seed-showcase --enqueue`. Сценарий предназначен для работающего приложения. Скриншоты и исторические трассы служат дополнительными свидетельствами, не заменяют проход.

## Подготовка оператора

1. Запишите `git rev-parse HEAD`, URL, дату, оператора, имена используемых компаний, job ID и начальное состояние денежного ledger. Укажите, новая это база или существующая. Сверьте SHA с `manifest.json`; для VPS оператор отдельно подтверждает SHA развёрнутого кода.
2. Проверьте `/health` и `/admin/jobs`, действующий ключ, согласованный лимит, `ready` PDF с правильными датами и завершённый `summarize`. Не запускайте новый OCR без согласования отправки документов. Не включайте сбор всей RSS перед короткой демонстрацией.
3. Откройте сотрудника и администратора в **разных профилях браузера**. Вкладки одного профиля делят cookie: вход администратором заменит сессию сотрудника.
4. Пароль берётся из собственного `DEMO_PASSWORD`; доступа на shenti.space нельзя выводить из локального `.env`. Оператор стенда отдельно передаёт жюри demo-доступы, без AI-ключей.
5. В baseline загружена только новость о решении по ключевой ставке от 23.10.2026. Фикстуры — пересказ публичного сообщения, дата сохранена. Не называйте их сегодняшней RSS-подборкой. `unseen` не добавляйте до шага D11.

## Основной путь и ожидаемые результаты

В таблице «PASS» означает наблюдаемый результат, а не заранее выставленную оценку. Заполните фактический результат, артефакт/ID и ошибку по каждому пункту.

| ID | Действие | Условие PASS |
| --- | --- | --- |
| D01 | Зарегистрировать новый email на `/register`, войти | Создан обычный пользователь; admin-права не выдаются |
| D02 | Подать заявку на `showcase_metal`, указать произвольную должность и интересы | Членство pending; закрытая аналитика ещё недоступна |
| D03 | Администратором подтвердить эту заявку в `/admin/memberships`; сотрудником обновить доступ | Active для правильного email/компании; приложение показывает выбранную компанию |
| D04 | Открыть «Бизнес-аналитику» | После worker появляется готовый персональный вывод. queued/failed не считается карточкой; явное partial фиксируется отдельно |
| D05 | Открыть baseline-анализ, причины и влияние | Разделены исходный факт, AI-интерпретация, условия и неизвестные параметры; сила без достаточных данных undetermined; есть предупреждение |
| D06 | Открыть новостное и корпоративное основания | URL/дата/исходный текст и поле компании соответствуют утверждению. Синтетическое происхождение профиля прозрачно |
| D07 | Проверить банковскую позицию | При наличии — настоящие документ, дата, страница, цитата и актуальность. Если материала нет — явное отсутствие позиции; это не PASS наличия позиции банка |
| D08 | Задать два последовательных вопроса, дождаться каждого; перезагрузить страницу | Ответы в контексте выбранных company/event, источники доступны, нет выдуманных сумм/долга; история сохранена. Отказ публикации фиксируется как отказ |
| D09 | Оценить полезность, подтвердить «Обсудить с менеджером», скрыть/вернуть | Состояния сохраняются после reload; подтверждение называет действие демонстрационным, запрос в банк не отправлен |
| D10 | Сравнить **одну новость** двумя компаниями × двумя должностями | Причины/механизм соответствуют подтверждённым признакам каждой компании. У «Строя» не появляется действующий кредит; неизвестные договорные условия не придуманы |
| D11 | Выполнить `seed-showcase --phase unseen --enqueue`, дождаться summarize и открыть новое событие | Новость об НКО ранее отсутствовала в baseline этого прохода. Нет выдуманной связи компании с НКО. Низкая релевантность/unknown допустимы; это не оценка held-out качества |
| D12 | Подать вторую заявку на `showcase_build`, подтвердить; переключить компанию | Профиль, лента, анализ и чат относятся к выбранной компании; чужая переписка недоступна |
| D13 | Проверить отрицательные случаи | Чужой chat/insight ID → 403/404 без содержимого; pending-пользователь не видит аналитику; отсутствие ключа/лимита не создаёт фальшивого готового ответа |
| D14 | Выйти/войти; на отдельном тестовом стеке пересоздать контейнеры без удаления томов | Членства, история, feedback и документы сохраняются; тестовый инфраструктурный отчёт PASS |

## Компании и вопросы

| Компания | Подтверждено в синтетическом профиле | Не подтверждено |
| --- | --- | --- |
| `showcase_metal` | Обработка металлов; кредитный продукт отмечен | Сумма/тип/ставка кредита, сроки и условия договоров, выручка |
| `showcase_build` | Строительство; кредитный продукт не отмечен, депозит отмечен | Остаток свободных средств, сумма/ставка депозита, доля ипотечных покупателей |

У каждого профиля есть бухгалтер и финансовый директор (email в README). Для бухгалтера: «Какие факты этой новости важны для учёта и какие условия договора надо проверить?». Для финансового директора: «Как событие может повлиять на ликвидность? Отдели факт, условный механизм и недостающие данные». Второй вопрос: «Каких данных не хватает, чтобы оценить силу влияния?». Проверьте также простой фактический вопрос о решении регулятора.

Различие должностей не означает, что все заголовки или формулировки обязаны быть уникальны. Сравнивайте основания и решение, а не косметическую перестановку слов. Изменение ключевой ставки не меняет автоматически ставку действующего договора.

## Собственная агентная трасса

Покажите этапы **план → контекст компании и новости → поиск банковских фрагментов → самопроверка → дополнительный поиск/исправление → проверка публикации**. Если повтор не понадобился, не изображайте его выполненным.

В Git сохранён [исторический пример трассы](agent-trace-v2.json) из F-16 с настоящими банковскими страницами, синтетической новостью и профилем. Его SHA и набор явно указаны; он не является свежей трассой D11. Текущая трасса хранится в `Trace`, её ID указан в `Insight.result.trace_id`. Операторская команда внутри API (передайте ID только своего тестового анализа):

```powershell
docker compose exec -T api python -c "import json; from app.db import session_factory; from app.models import Insight, Trace; db=session_factory()(); obj=db.get(Insight, 'INSIGHT_ID'); assert obj is not None; trace=db.get(Trace, obj.result['trace_id']); assert trace is not None and trace.user_id == obj.user_id and trace.company_id == obj.company_id; print(json.dumps(trace.result, ensure_ascii=False, indent=2)); db.close()"
```

Если команда завершается ошибкой, сохраните ID анализа/job и проверьте наличие трассы. Не записывайте историческую трассу под ID новой генерации. Команда требует операторского доступа к контейнеру и не используется обычным пользователем для обхода HTTP-прав.

## Протокол независимого повтора

Другой участник заполняет: дата/ФИО, SHA из manifest, SHA развёрнутой версии, окружение, D01–D14 (PASS/FAIL/N/A с причиной), event/job/insight ID, итог бюджета, найденные дефекты. Не включайте пароль/ключ/сессионную cookie. Критический дефект изоляции, атрибуции или выдуманный факт блокирует GO. Невыполненный шаг обозначается N/A, а не PASS. Автоматическая проверка чистого Compose не заменяет эту подпись.

Для презентации откройте [слайды](../release/presentation.html), затем переключитесь в работающий сервис. Рекомендуемый порядок на 7–10 минут: точка входа → готовый вывод → причины/источник/дата банка → сравнение 2×2 → вопрос/история → действие/feedback → новая новость/неизвестные → трасса/ограничения.
