Дополняет закрытые задачи: F-01.

**Зависимости:** уже готовые компоненты, новых блокеров нет.

**Условия:** Использовать уже слитые API/AI; дополнительные зависимости: нет новых блокирующих задач.

**Что сделать:**

1. Поверх выполненной F-01 согласовать с Алексеем и Романом schema_version и совместимость v1. Добавить personalized_summary, mechanism, impact_level={low,medium,high,undetermined}, impact_reason с evidence, time_horizon, assumptions, relevance_status/valid_from/valid_until/review_after/relevance_reason и policy_version/disclaimer.

Количественный scenario допускается только с input_refs, единицами/периодом, формулой, предпосылками и диапазоном; не добавлять выдуманные суммы/вероятности. next_actions — allowlist, не инструкция к произвольному инструменту.

Дать примеры: сильное доказанное влияние; неизвестная сила; историческая/отсутствующая позиция банка; недостаточный профиль; длительный действующий инсайт. Определить v1 fallback и инвалидирование кеша при смене schema/semantics/prompt.

### F-14. Генерировать доказанный механизм влияния вместо пересказа новости

**Статус:** Новая задача. **Приоритет:** P0. **Срок:** 22.10, 16:00 МСК.

Дополняет закрытые задачи: F-05, F-06, F-07.

**Зависимости:** F-13, A-14.

**Условия:** Использовать уже слитые API/AI; дополнительные зависимости: F-13, A-14.

**Что сделать:**

1. Использовать выполненные F-05/F-06/F-07 и нормализованный CompanyContext v2. Краткий вывод строится как событие → наблюдаемый признак → условный механизм → риск/возможность → действие; для качественного ready-инсайта нужны независимые релевантные факторы либо явное ограничение вывода.
2. Оценивать impact по опубликованной рубрике: сила подтверждённой экспозиции, срочность/масштаб и неопределённость; нет данных → undetermined, не low. Разделить event published_at, горизонт воздействия и review/validity самого инсайта, включая долгосрочный эффект. Количественный расчёт выполнять кодом только из подтверждённых входов.
3. Для разных компаний и должностей менять механизм/приоритет, не только имя. Учитывать разрешённые групповые/платёжные связи без «поставщик/владелец/импортёр» по одному ребру. Отсутствие bank_view не блокирует внешний анализ; исторический документ обозначать датой, не сегодняшней позицией банка.

**Результат в коммите:**

- Генерация v2 и краткий preview, рубрика impact/relevance, trace evidence/assumptions, разные примеры одной новости.

**Приёмка:**

1. Одна новость даёт обоснованно разные выводы для credit/non-credit и двух должностей; профиль с неизвестными полями не получает выдуманные кредиты.
2. У каждого механизма есть event + company evidence; необоснованный качественный уровень/число/срок отклоняется или помечается undetermined.
3. Те же данные переиспользуют кеш; изменённые версии контракта/семантики/профиля/события/корпуса дают новую идентичность.

**Коммит:** `feat(ai): generate grounded business impact previews`. **Основания:** CASE, WEB.

**Зависимости:** F-14.

1. Расширить F-09: ловить не только отсутствие ссылки, но смысловые пресуппозиции («существующие кредиты» при неизвестном долге), подмену гипотезы фактом, суммы без единиц/периода, возраст банковской позиции, перенос признаков между компаниями.
2. Retrieval/evidence возвращают название/дату/страницу/версию и temporal status документа. Не применять только универсальное отсечение «год» для всех тем; сравнивать содержание и период применения. Если актуальность неизвестна — не утверждать сегодняшнюю позицию; оставить обоснованный внешний вывод и unknowns.

Внести regression для S5 из текущего ai-evaluation, FTS без направления, CITY_NAME без местоположения завода, self-payment без внешнего оборота, GROUP_ID без собственности, revenue=1000 и неподтверждённого 2025/периода платежей.

**Результат в коммите:**

- Семантические/временные валидаторы, структурированный отчёт claim_id, regression fixtures и обновлённый RAG envelope.

**Приёмка:**

1. Все отрицательные fixtures блокируются до ready-публикации или превращаются в явную гипотезу/unknown; Disclaimer не заменяет валидацию.
2. Правильный вывод сохраняет источники; ложный банковский факт не маскируется валидным source_id.
3. Карточка и чат одинаково обрабатывают неполный профиль, старый bank evidence и конфликт источников без выдуманного разрешения конфликта.

**Коммит:** `fix(ai): validate semantic and temporal grounding`. **Основания:** CASE, WEB, CODE.
