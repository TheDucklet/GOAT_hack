Продуктовые события A16.

POST /companies/{company_id}/product-events принимает impression и open для собственной сохранённой карточки. Сеанс определяется серверной cookie. Клиент не задаёт время, пользователя, версию или признак исключения. Примеры находятся в docs/contracts/interaction-examples.json. DTO и правила доступа опубликованы в OpenAPI.

Сервер самостоятельно записывает chat при постановке вопроса в очередь, action при демонстрационном действии, hide и restore при персональном скрытии и восстановлении, feedback при сохранении оценки. Событие chat означает отправленный вопрос, а не успешный ответ модели. Успех обработки определяется статусом задания. Тексты вопроса, ответа, обратной связи и содержимое профиля в продуктовую таблицу не копируются.

Для каждого события сохраняются серверное время UTC, пользователь, компания, событие новости, идентификатор карточки при его наличии, версии и хеш серверного сеанса. Два impression одной версии карточки в одном сеансе имеют одинаковый ключ и дают одну запись. Новый вход образует новый сеанс. Open также считается один раз на версию в сеансе. Событие действия связано с его постоянным идентификатором и не дублируется после повторного входа. Chat связан с идентификатором сообщения. Feedback различается по оценке и версии карточки.

Администраторы помечаются admin. Запросы с признаками bot, crawler, spider или headless в User Agent помечаются bot. Демо аккаунты домена goat.example.org, адреса из PRODUCT_TEST_EMAILS и окружение test помечаются test. Это исключение известных тестовых источников, а не доказательство распознавания всех автоматизированных клиентов. Помеченные события сохраняются для проверки, но не участвуют в новых продуктовых агрегатах.

GET /admin/product-metrics возвращает агрегаты только для администратора. Counts содержит количества учитываемых событий за срок хранения. Open rate вычисляется как open / impression. Action rate вычисляется как action / open. Hide rate вычисляется как hide / impression. Это отношения числа событий, а не уникальных людей или подтверждённых банковских конверсий. Если знаменатель равен нулю, сервер возвращает null. Интерфейс должен показать N/A. События действий без предшествующего показа могут давать отношение больше единицы. Для строгой воронки потребуется отдельная когортная агрегация по сохранённым идентификаторам.

PRODUCT_EVENT_RETENTION_DAYS по умолчанию равен 90 и ограничен диапазоном от 1 до 365. Планировщик удаляет просроченные продуктовые события. Даже до удаления агрегаты не включают события старше срока хранения. Основные Feedback и DemoAction хранятся отдельно и не удаляются этой политикой.

POST /companies/{company_id}/dismissals принимает event_id, необязательный insight_id и hidden. Без insight_id скрывается событие для данного пользователя и компании во всех версиях. С insight_id скрывается только соответствующий cache key. Восстановление должно использовать тот же охват. Оно не снимает другие персональные исключения и не меняет Event.visible. GET того же пути возвращает собственные исключения с limit и offset. Обе версии ленты применяют персональные исключения на сервере.

POST /companies/{company_id}/demo-actions принимает только action_type contact_manager. Идемпотентность ограничена пользователем и компанией. Повтор того же ключа и содержимого возвращает прежнюю запись. Иное содержимое с тем же ключом даёт 409. Результат всегда содержит mode demo и status recorded. Внешние CRM, почта и банковские системы не вызываются. Запись не является банковской заявкой.
