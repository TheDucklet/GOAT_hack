Приёмка A16 от 22 октября 2026 года.

Реализованы персональные исключения по пользователю, компании и событию либо версии карточки. Состояние сохраняется между входами. GET собственных исключений позволяет восстановить скрытый элемент после перезагрузки. Персональные операции не изменяют глобальный Event.visible. Обе версии ленты применяют исключения на сервере.

Добавлено идемпотентное действие contact_manager. Ответ содержит mode demo и status recorded. Повтор ключа возвращает прежнюю запись, изменение содержимого с тем же ключом даёт 409. Неподдерживаемый тип действия даёт 422. Внешних отправок нет.

Продуктовые события содержат серверные время, сеанс и версии. Повторные показы одной карточки в одном сеансе не дублируются. Администраторы, известные боты и тестовые аккаунты помечаются и исключаются из агрегатов. Срок хранения по умолчанию составляет 90 дней. Пустой знаменатель возвращает null для отображения N/A. Формулы и ограничения изложены в docs/product/events.md.

Проверены изоляция двух пользователей с доступом к одной компании, чужая компания, чужая карточка, CSRF, повторный вход, отдельность глобального скрытия, ограничение версии, идемпотентность после повторного входа, конфликт ключа, allowlist, исключения bot и admin, срок хранения и пустые метрики. DTO примеры проверяются backend и frontend по OpenAPI. Миграция 0005 создаёт таблицы действий и продуктовых событий. Таблица персональных исключений подготовлена в миграции 0003 задачи A15.

Визуальные экраны действий и продуктовая аналитика интерфейса остаются задачами frontend. HTTP контракт и примеры готовы для подключения. Продуктовые отношения в этой версии считаются по событиям, а не по уникальным людям или завершённым банковским операциям.
