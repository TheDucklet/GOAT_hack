AI обработал новость, подготовил персональную карточку v2 и ответил в чате. Подготовка одного снимка вместе с ожиданием очереди заняла 34.466 секунды. Повторное чтение карточки заняло 0.015 секунды. Это одиночный живой сценарий, а не оценка p95 модели. Синтетический профиль компании явно отделён от публичной новости и реальной страницы банковского документа.

Шлюз сообщил расход 0.540285 рубля за 11 вызовов. В отчёте usage учтены 15 926 входных и 4098 выходных токенов. Все 11 вызовов завершились успешно и потребовали по одной транспортной попытке. В число вызовов входит OCR страницы. Для приёмки действовал дополнительный локальный предел 10 рублей. Стандартный дневной предел 500 рублей и начало суток в 03.00 по Москве сохранены согласно предоставленной инструкции организаторов.

Сохранение бюджета исправлено. Резерв записывается и синхронизируется до отправки запроса. API и worker используют журнал под общей межпроцессной блокировкой. Каждая повторная транспортная попытка требует нового резерва. Незавершённый резерв переживает аварийный выход. Повторное списание одного request_id не удваивает расход. Таймаут не считается доказательством бесплатного вызова и сохраняет консервативную оценку расходов.

Файловый AI кеш сохраняется на томе и защищён общей блокировкой от одновременной генерации одного ключа. DB tools предоставляют версию корпуса. Изменения настроек модели, промптов и поколения учитываются в идентичности кеша. Кешированная карточка получает свежий AI trace_id для нового запроса и не конфликтует с ранее сохранённой трассой.

После пересоздания контейнеров бюджет остался равен 0.540285 рубля. Карточка, пользовательский доступ и история из двух сообщений сохранились. Содержимое кеша совпало. Дополнительная проверка app.ai.bridge в новом процессе API подтвердила cache hit и свежий trace_id при неизменном расходе. Три проверки межпроцессных резервов, идемпотентного списания и единственного вычисления кеша прошли в Linux контейнере. Те же сценарии проверены локальными процессами Windows.

Добавлены received_at, enqueued_at, started_at, ready_at, attempts и идентификатор задания в HTTP контракте. AI трасса связывается с job_id. Административные метрики показывают возраст очереди, статусы, повторы и локальный бюджет. Логи usage содержат технические параметры без ключа и полного текста запросов. Проверено отсутствие значения фактического ключа во всех неигнорируемых файлах репозитория.

Отдельный управляемый тест подтвердил максимум девять транспортных попыток для одного повторяемого вызова при трёх попытках шлюза и трёх запусках задания. В живом окружении настройки давали максимум шесть, фактических повторов не было. Это предел одного вызова при повторах задания. Многошаговый агент выполняет несколько отдельных ограниченных вызовов. Общий расход ограничивается резервами бюджета. Для недоступности модели и исчерпания бюджета проверены явные ошибки и deferred без подмены результата готовой карточкой.

Межпроцессная синхронизация предназначена для одного файлового хоста. Вызовы коллег за пределами этой сборки локальный журнал не учитывает. Сумма usage и записи бюджета является наблюдением этого прогона, а не выпиской по всем расходам команды. Окончательный общий предел применяет командный шлюз.

Артефакты живой проверки находятся в a17-live.json и a17-usage.json. Файл compose.acceptance.yaml воспроизводит ограниченную локальную конфигурацию. Серверный .env.ai и исходный PDF в Git не включаются.
