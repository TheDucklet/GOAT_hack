## Браузерные доказательства

- [14 проверок dev-режима](r-01-browser.json), [desktop](r-01-desktop.png), [mobile](r-01-mobile.png).
- [Проверка HTTP-транспорта production-сборки](r-01-http.json): фиксируются только пути и признаки совпадения cookie/CSRF, без значений cookie, паролей или токенов.

Production HTTP browser harness перехватывает сетевые ответы и возвращает JSON A-01. Он проверяет настоящий browser fetch, маршрутизацию и работу cookie/CSRF, но **не является проверкой живого backend**. В ветке A-01 бизнес-endpoints возвращают 501; живой auth появится в A-02/A-03. Dev-mock тоже не объявляется реализацией backend или AI.

## Воспроизведение

Из frontend/ с Node.js 24:

```powershell
npm ci
npm run contracts:check
npm test
$env:VITE_API_MODE='http'
npm run build
npm run preview
```

В другом терминале при работающем preview:

```powershell
python tests/http_smoke.py --channel msedge
```

Для dev-проверок запустить отдельный dev-сервер с `VITE_API_MODE=mock`, затем:

```powershell
python tests/browser_smoke.py --channel msedge
```

Python-скрипты требуют Playwright 1.58.0; установка и вариант Chromium описаны в frontend/README.md. Основные unit/component/schema-тесты требуют только npm-зависимостей и работают без Python, backend и секретов.
