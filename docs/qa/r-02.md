# Проверка R-02

Дата: 20.10.2026. Ветка: `r-02/roman/compose-ci`. Основа: frontend R-01 (`714888a`) и опубликованный backend A-13 (`4bd0d46`), объединённые коммитом `042b1f5`.

## Реализовано

- `compose.yaml`: web, api, worker, postgres; два постоянных named volumes; миграции перед HTTP API; готовность зависимостей по healthcheck; scheduler только в worker.
- Multi-stage frontend Dockerfile, nginx SPA fallback и same-origin API/PDF proxy; образы закреплены digest.
- `.env.example` и необязательный `.env.ai` только для API/worker. Пользователь подтвердил, что список переменных Фёдора можно дополнить позже; сейчас используются только известные AI_MODULE/AI_GENERATION_VERSION.
- CI: npm ci, generated types/build/tests; backend requirements.lock, pip check/Ruff/существующие тесты на PostgreSQL; запуск и пересоздание всего Compose-стека без реальных секретов.
- Инструкция миграций/seed и воспроизводимые smoke scripts.

### Локальная проверка 20.10.2026

Проект `goat-r02-check` запущен на Windows / Docker Desktop 4.40.0, Engine 28.0.4, Compose 2.34.0. Все четыре сервиса healthy, frontend доступен на `http://127.0.0.1:8080`, `/health` возвращает 200. [Локальный отчёт Compose](r-02-local-compose.json): все 23 проверки прошли, включая сохранность записей, сессии и документа после пересоздания контейнеров. Тома сохранены, стек оставлен работающим.

В том же backend-образе повторно выполнены все 71 существующий тест с PostgreSQL, Python 3.12.14 и зависимостями из requirements.lock: [вывод pytest](r-02-local-backend.txt). Для тестов созданы отдельные базы `goat_test` и `goat_a01_test`; `docs/contracts` подключён только для чтения в `/srv/docs/contracts`, так как эти опубликованные файлы не входят в контекст backend-образа. Первый запуск без этого подключения дал 68 passed и три FileNotFoundError; с доступными контрактами весь набор прошёл, изменений кода приложения не потребовалось.

В Microsoft Edge headless проверены настоящий вход через UI/API, HttpOnly-cookie, восстановление страницы с активной сессией, выход и ответ `/api/me` 401 после него; необработанных ошибок браузера нет. [Отчёт браузера](r-02-local-browser.json), [скриншот страницы входа](r-02-local-login.png).

Изначально локальную сборку задержали загрузки слоёв Docker Hub. Дополнительно Docker Desktop после простоя возвращал HTTP 500 / `no route to host`; штатный перезапуск восстановил движок. Для обхода остановок загрузки базовые образы скачаны из официального registry через Windows небольшими диапазонами и импортированы OCI-архивами. SHA-256 исходного index, manifest, config и каждого слоя проверены; RepoDigests импортированных Python/Node/nginx точно совпадают с Dockerfiles. После импорта стандартная команда `docker compose -p goat-r02-check up --build -d --wait` успешно собрала и запустила стек. Версии, Dockerfiles и Compose для обхода сети не менялись.

Ранее также локально прошли Compose config, передача будущих AI-переменных, generated types, 45 frontend-тестов и build. Реальные AI-ключи для этих проверок не использовались.

## Повторение

```powershell
python scripts/verify_compose_config.py
docker compose -p goat-r02-check up --build -d --wait
python scripts/verify_compose.py --project goat-r02-check --base-url http://127.0.0.1:8080
```

Второй скрипт проверяет реальный HTTP, миграции/повторный seed, запись PostgreSQL, HttpOnly-сессию и shared document volume; пересоздаёт только явно указанный проект без удаления томов и проверяет восстановление данных. Все аккаунты и файлы синтетические, значения паролей/cookie/CSRF не записываются в отчёт. Команды Docker запускаются argv-массивами без shell.
