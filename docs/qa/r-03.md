# Проверка R-03

Дата: 20.10.2026. Ветка: `r-03/roman/auth-memberships`, основа R-02 (`4e415b9`) с опубликованным backend A-13 (`4bd0d46`). Backend и HTTP-контракт не изменялись.

## Результат

- `/login` и `/register`: email/password, серверная HttpOnly-cookie, выход через `/auth/logout`; 409 занятого email рядом с полем. Пароль, cookie и CSRF не сохраняются в localStorage/sessionStorage.
- `/app/companies`: все собственные active/pending/rejected членства, заявка по company_id и редактирование position_text/interests отдельно для каждого членства. Список должностей не ограничен. Имена берутся только из доступных компаний; для остальных показан идентификатор.
- Pending/rejected не дают доступ к компании. Кнопка «Обновить доступ» перечитывает серверные членства и доступные компании; системная роль не выводится из должности.
- Единый API-клиент использует cookie credentials и CSRF для заявки/профиля. Все тела запросов соответствуют опубликованным MembershipIn/ProfileIn; прав доступа и статуса в них нет.

## Воспроизведение

На локальном стеке с `seed-demo`, из корня репозитория:

```powershell
docker compose up --build -d --wait
docker compose exec api python -m app.cli seed-demo
python frontend/tests/membership_smoke.py --channel msedge
```

Для уже запущенного проекта `goat-r02-check` первые две команды выполняются с `-p goat-r02-check`. Python-скрипт требует Playwright 1.58.0 и Edge; `--channel` можно не задавать при установленном Playwright Chromium. Он создаёт нового синтетического пользователя/членство, меняет администратором только это новое членство и оставляет его active. Существующие данные не изменяются. Для изменённого seed-пароля используется R03_ADMIN_PASSWORD из окружения. Отчёт и скриншоты — `artifacts/r03/`, секреты в отчёт не включаются. Реальные AI-ключи не требуются.

Unit-проверки: `cd frontend`, затем `npm test`, `npm run contracts:check`, `npm run build`. Production-сборка обращается к настоящему API; mock допускается только при отдельном dev-запуске.

Формальное закрытие задачи требует командного ревью и объединения PR в общую ветку по TASKS.md. Реализация и локальная интеграционная проверка выполнены; общая main не изменялась.
