# R-07 — минимальное управление доступом

Ветка: `r-07/roman/access-management`; исходный main: `728599a8f68c0ce4424d802373c89bbb958d0f9d`. Локальная приёмка: 22.10.2026, МСК. Требования: [план Романа](../planning/roman.md), существующий A-03 включён в main. Публикация и слияние фиксируются отдельно от этого отчёта.

## Выполнено

- `/admin/users`: email, ID, статус, системная роль только для чтения; блокировка/разблокировка с подтверждением и явным результатом. Собственный аккаунт не предлагает блокировку.
- `/admin/memberships`: пользователь, точный ID компании/членства, статус заявки, произвольная должность и интересы; approve/reject/revoke с подтверждением. `/admin/users/memberships` перенаправляет сюда. `/admin` сохраняет сводку.
- Общие admin API, пагинация по 50, отмена запросов, один PATCH за попытку, 15-секундный таймаут, ручной повтор. Нативный модальный диалог поддерживает клавиатуру и отмену. Статус меняется только по подтверждённому ответу; чужой id или неверный статус не создают успех.
- 401/403 очищают административные записи; обычный пользователь не получает данные напрямую через URL или API. Cookie, CSRF, серверная регистрация, роли, аудит и отзыв сессий используют существующий backend. Backend-код, OpenAPI, миграции и runtime-зависимости не менялись.
- [Инструкция оператора](../demo/access-management.md): готовые demo-аккаунты, два ЛПР компании A, аккаунт с A/B, операции A-03 и отложенные P2 (редактор ролей, поиск/фильтры, отдельный onboarding).

1. Открытие и отмена подтверждения через Escape не отправляют PATCH. Approve делает компанию доступной после пользовательского обновления `/me`; до него серверный feed возвращает 403.
2. Два разных user получают компанию A, один из них — A/B. Произвольная должность сохранена, системная роль остаётся user.
3. Reject виден в строке и сохраняется после reload.
4. Block через UI отзывает ранее действовавшую сессию: `/me` → 401 и защищённая страница возвращается к login.
5. Unblock не восстанавливает старую сессию: требуется новый вход, после него доступ снова работает.
6. Обычный user получает 403 на `/admin`, `/admin/users`, `/admin/memberships`, alias и обоих GET API; чужих записей на экране нет.
7. Списки и подтверждение помещаются в 390 px; browser storage пуст. За весь сценарий отправлены ровно **5** явных PATCH, каждый содержит только status.

## Границы

A-03 возвращает в MembershipOut user_id/company_id без email и названия компании. UI читает справочник пользователей страницами по 200 один раз, показывает email и точный company_id; выдуманных названий нет. При большом справочнике дальнейшее улучшение P2 — серверные метаданные/поиск. Статус может измениться другим оператором: «Обновить список» перечитывает актуальное состояние. Уход со страницы не откатывает уже принятое изменение, а timeout не доказывает его отсутствие.

Фикстуры допускаются только в пустой `goat_r07`; пароль случаен, остаётся в памяти и передаётся через stdin. Пользовательские БД и данные не менялись. Результаты и тестовые тома сохраняются после остановки. Для демонстрации R-07 используйте HTTP-режим; dev-mock R-01 не заменяет административный backend.
