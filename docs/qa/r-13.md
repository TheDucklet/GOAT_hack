# R-13: лента готовых персональных инсайтов

25.10.2026, МСК. Ветка `r-13/roman/personalized-feed` от main `c732999` (F-17).

Лента теперь показывает сохранённый персональный вывод и механизм до открытия новости, с уровнем/основанием влияния, горизонтом, актуальностью и неизвестными. Новость — отдельное основание; её raw summary не выдаётся за персональный инсайт. Notice берётся из общего `notice_v1`.

## Устройство

- `createAnalyticsApi.feed` использует `contract_version=v2`; пагинация и polling передают один snapshot_id. Нет POST генерации на render и запросов за каждой карточкой. Сохранённый insight_id передаётся в существующий AnalyticsSelection; деталь делает одно чтение выбранной карточки.
- Snapshot проецирует mechanism, impact_reason, time_horizon, relevance_reason, valid_from/valid_until/review_after и unknowns из сохранённых результатов. Insight читаются одним SQL-запросом на страницу; AI не вызывается из GET. Уточнена проверка event_id сохранённой карточки вместе с company/user.
- Новые wire-поля необязательны для совместимости; OpenAPI, TypeScript, JSON Schema и fixtures генерируются из backend-схем. Неподготовленный элемент не может содержать персональные поля. Смена event/profile/focus/corpus/contract инвалидирует прежний preview.
- Pending опрашивается раз в 2 секунды до 120 секунд. Готовая лента перепроверяется раз в 45 секунд и при возврате в окно. Stale скрывает все прежние preview; ручное обновление запрашивает актуальный snapshot. Сетевая ошибка сохраняет загруженные страницы; 401/403 и неподдерживаемая wire-схема убирают недоступные данные и выбор.
- Пустая отфильтрованная страница не обрывает пагинацию: используются серверные frozen offsets. Смена компании/пользователя сбрасывает состояние и отменяет старые запросы; начальная загрузка feed не очищает чат из URL.
- Использованы существующие HttpClient, CompanyProvider, AnalyticsSelection, ClaimView, EvidenceLink и InsightNotice. Подписи влияния/актуальности общие для preview и детали; нового API-клиента, очереди и слоя генерации нет.

## Повторение

Из корня репозитория, PowerShell; нужны Docker, Node 24.22, Python с Playwright/httpx и Edge:

```powershell
$env:IMAGE_TAG='r13-check'
$env:AI_ENV_FILE='.env.ai.example'
docker compose -p goat-r13-check -f compose.yaml -f frontend/tests/compose.r13.yaml up --build -d --wait
python frontend/tests/prepared_feed_smoke.py --project goat-r13-check --channel msedge
docker compose -p goat-r13-check -f compose.yaml -f frontend/tests/compose.r13.yaml stop
```

Для следующего прогона требуется новое имя `goat-r13-*` и свободный порт 8094: существующие данные фикстура не заменяет. Все модели в этом стеке синтетические; ключ явно пуст. Тест не перехватывает HTTP и не отправляет данные во внешний AI.

## Граница приёмки

R-13 проверяет готовую ленту и её согласованность с действующим backend-контрактом. Семантическая корректность произвольной реальной генерации F-16 этим прогоном не подтверждается. Известные блокеры фактов/банковской атрибуции и ручная калибровка должны быть закрыты в F-16; после них общая приёмка R-10 и freeze R-11 выполняются заново. Слияние R-13 не является разрешением объявлять весь MVP готовым.
