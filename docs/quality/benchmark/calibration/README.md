# Инструкция разметчику: калибровка и контроль оценщика

Нужно независимо оценить, следует ли утверждение из его источников. Метки ставит человек, не автор генератора и не ИИ-агент. Не открывайте `selection.json`, результаты судьи и файлы `runs/`, не обсуждайте метки до сдачи обоих файлов.

## Что в листах

| Файл | Строк | Назначение |
| --- | --- | --- |
| `calibration-sheet.csv` | 42 | настройка оценщика: шесть уникальных критических формулировок, по пять утверждений на раздел и шесть сценариев |
| `control-sheet.csv` | 30 | контроль настроенного оценщика, по пять утверждений на раздел, его строки не используются при настройке |

Колонки: `row_id`, `section` (раздел карточки), `statement_type` (`fact`, `hypothesis` или `scenario`), `claim` (утверждение), `sources` (полный текст цитируемых источников с датой и страницей для материалов банка), `verdict`, `premises_supported`, `conclusion_acceptable`, `marking_correct`, `comment`. Заполняются только четыре последние колонки перед `comment` и сам `verdict`.

## Как оценивать

**Факт и позиция банка (`statement_type` = `fact`).** Заполните только `verdict`.

| Значение | Когда ставить |
| --- | --- |
| `supported` | весь смысл утверждения следует из источников: действующее лицо, действие, направление изменения, отрицание, модальность (факт или прогноз), числа, единицы, период, дата, авторство |
| `unsupported` | часть утверждения не следует из источников: добавлено направление изменения, причинная связь, влияние на третью сторону, неверно назван субъект, прогноз подан как свершившийся факт, авторство источника не подтверждено |
| `contradicted` | источники утверждению противоречат |

Подтверждённая первая половина сложного предложения не подтверждает добавленную вторую: если хотя бы одна смысловая часть не следует из источников, ставьте `unsupported`. Для позиции банка источниками служат только материалы банка из колонки `sources`, совпавшее число из новости позицию банка не подтверждает.

**Гипотеза и сценарий (`statement_type` = `hypothesis` или `scenario`).** Гипотеза не обязана повторять источник дословно, но проверяется по частям.

| Колонка | Значение |
| --- | --- |
| `verdict` | `supported`, если фактические предпосылки подтверждены источниками и условный вывод допустим; `unsupported`, если вывод подменяет неизвестную предпосылку фактом либо добавляет свойство компании, которого нет; `contradicted`, если вывод противоречит источникам |
| `premises_supported` | `yes`, если все фактические предпосылки (события, компании, банка) есть в источниках; `no`, если хотя бы одной нет |
| `conclusion_acceptable` | `yes`, если вывод явно условный, не подменяет неизвестное фактом, не противоречит данным и называет условие применимости; `no` иначе |
| `marking_correct` | `yes`, если утверждение правильно помечено как гипотеза или сценарий (не подано как факт); `no` иначе |

Слова «если» и «возможно» сами по себе не оправдывают выдуманное свойство компании. Наличие банковского продукта в профиле не подтверждает действующую задолженность, договор или величину экспозиции. Запись ФТС, платёж и код группы не подтверждают импорт, поставку, собственность или планы компании.

**Сценарий** (`row_id` на `S`). Количественный сценарий допустим только с названными входными данными, единицами, периодом, проверяемой формулой, предпосылками и диапазоном. Сумма или вероятность, которых нет во входах, делают сценарий `unsupported`.

Колонку `comment` заполняйте для всех строк с `unsupported` или `contradicted`: одной фразой, какая часть не следует из источников.

## Как сдать

Сохраните копии листов как `calibration-labels-<имя>.csv` и `control-labels-<имя>.csv` (имя латиницей) в UTF-8 (в Excel «CSV UTF-8»), колонки не меняйте, все строки заполните. Расхождения потом разбираются вместе, обе исходные метки сохраняются.
